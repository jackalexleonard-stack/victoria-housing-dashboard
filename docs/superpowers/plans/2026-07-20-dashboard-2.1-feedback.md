## F1 — staleness chip honesty (`source unavailable` overfiring)
`staleness()` returns `failed` purely from `status === 'failed'`, i.e. the *last fetch attempt* — even when the retained data is current. Rule change in `web/src/lib/staleness.ts`:
- failed + no `last_data_date` → `failed`, "No data · source unavailable" (unchanged)
- failed + gap > 1.5×cadence → `failed`, "Data to {period} · source unavailable" (unchanged)
- **failed + gap ≤ 1.5×cadence → `fresh`, plain "Data to {period}"** (new: a failed fetch that hasn't cost currency stays quiet)
Masthead count in `App.tsx` switches from raw `status==='failed'` to `staleness(entry, now).kind === 'failed'` (today that honestly means 2 — auctions + REIV — not 5). Tests: new staleness cases + masthead count against the edge fixture.

## F2 — x-unified tooltip (all lines at the hovered date)
`nearest()` bisects the merged flat array by time only → with multiple lines, hover shows an arbitrary single point. Add `atTime(flat, t)` to `chartMath.ts`: nearest timestamp t*, then one point per line at t* (a line without a point exactly at t* contributes its nearest-within-half-cadence or is omitted — keep it simple: exact-t* matches; lines are same-series metrics sharing dates in practice). `LineChart` hover state becomes `{t, points[]}`: crosshair + a dot per line + a multi-row tooltip (swatch · line name · value via per-line unit). Vertical mouse position no longer selects the line. Touch behaviour unchanged.

## F3 — legends
`LineChart` renders a legend row (swatch + name, wrapping, tokens only) whenever `lines.length > 1`, in both card and detail contexts; the compare/y2 series keeps its name tied to the right axis. No legend for single-line charts.
