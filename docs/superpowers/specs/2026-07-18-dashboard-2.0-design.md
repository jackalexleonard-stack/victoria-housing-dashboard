# Dashboard 2.0 — design spec

**Date:** 2026-07-18 · **Status:** approved pending user review
**Supersedes:** the front-end half of `BUILD_BRIEF.md`'s locked stack (Streamlit → React SPA on GitHub Pages). The pipeline/data-layer decisions in the brief are unchanged.
**Reviewed by:** 5-lens specialist panel + adversarial verification (52 agents, 2026-07-18); all 16 confirmed changes are folded into this spec. Strategic context: `PRODUCT.md`.

## 1. Summary

Dashboard 2.0 replaces the Streamlit app with a bespoke React SPA — a single-page daily briefing on the Victorian housing market for the owner and their team of housing economists. The pipeline, data files, and daily GitHub Actions run are untouched except for one new export step. Hosting moves to GitHub Pages; cost stays $0. The Streamlit app stays live until 2.0 reaches content parity and is then retired.

Personality: **warm, editorial, crafted** (see PRODUCT.md). The dashboard reads like a data publication: every chart leads with a computed plain-language finding; provenance is everywhere; nothing pretends.

Decisions made during design (recorded so they aren't relitigated):

- Identity: **evolve** the Scandi cream identity, not replace it.
- IA: **rethought** around a global filter bar — one scrollable briefing, no tabs.
- Modal actions: CSV download, copy deep link, view source, compare — all four.
- Mobile: **first-class**. On phones, tapping a chart opens its detail view (no touch-scrubbing on the main page); scrubbing works inside the detail view.
- Launch scope: **full content parity** with the Streamlit app before cutover.
- Accessibility: WCAG 2.1 AA, with chart keyboard access via **equivalents** (finding + data table), not per-point traversal.
- Domain: none — links live at `https://jackalexleonard-stack.github.io/victoria-housing-dashboard/`.

## 2. Identity evolution

Kept from the shipped Scandi identity: Flexoki palette (`bg #FAF7EF`, `bg2 #F2F0E5`, `card #FFFEFA`, `ink #1C1B1A`, `muted #575653`, `blue #205EA6`, `clay #BC5215`, up/down/warn `#00824D`/`#AF3029`/`#AD8301`, chip tints), Inter 400/500/600 with `tnum` for all UI/labels/data, Material Symbols Rounded, pale-tint chips (never solid fills), whitespace over dividers, chart colorway `#205EA6 #BC5215 #24837B #66800B #5E409D #878580`.

Evolved:

- **Newsreader** (Google Fonts, opsz axis) joins as the display serif: findings, section titles, masthead. Inter keeps every control, label, axis, and number. Serif display + sans UI on a genuine contrast axis.
- **Findings, not figures.** Every chart card leads with a computed finding headline set in Newsreader ("Approvals still running below Accord pace"); the series name is demoted to the caption line with source and staleness chip.
- **Colour roles sharpen:** blue = interactive only (links, selection, active filter, focus); clay = editorial emphasis only (event annotations, the highlighted latest point). Never mixed.
- **Event annotations:** thin clay vertical markers with small labels — cash-rate moves (derived from the `au_cash_rate` series at export time), the Accord start date (2024-07-01, static) — only on charts where relevant.
- **Motion** (product register): 150–250ms state transitions; one-time chart line draw-in on first viewport entry; filter changes crossfade (~200ms); no orchestrated page-load choreography. Every animation has a `prefers-reduced-motion` alternative (instant or crossfade) — implemented globally via `MotionConfig reducedMotion="user"` plus CSS media queries.
- Design tokens live in one TypeScript module (`web/src/theme/tokens.ts`) emitted as CSS custom properties; Tailwind v4 reads them. Token values are pinned by Vitest tests ported from `tests/test_theme.py` (exact hex, colorway, type scale) so the identity keeps its safety net when `app/` retires.
- AA contrast is verified at token level before any component work (body text ≥ 4.5:1 on all three surfaces; muted `#575653` on cream passes; `faint #6F6E69` is caption-size-only).

## 3. Information architecture

One scrollable page + URL-driven overlays. Order:

1. **Masthead** — wordmark (Newsreader), "as at {date}", last-run status chip.
2. **Sticky filter bar** — date range presets `1y · 3y · 5y · 10y · All` (default **5y**); geography `Melbourne · Regional Vic · Victoria · Australia`; scrollspy section chips (Today, Prices, Rents, Supply, Money, People, Social, World, News). Collapses on mobile to a compact row + bottom-sheet.
3. **Today briefing** — lead finding (large card), two secondary findings (all three = precomputed hero picks), "changed this week" strip (from `last_changed`, 7-day window), **top news story cards** (precomputed story ranks, thumbnails where available, tags shown), optional digest text when present.
4. **Themed sections**, narrative order: **Prices** (vic_hvi, au_hvi, vic_median_price, au_dwelling_stock mean price) → **Rents & vacancy** (vic_rents, affordable share, vic_vacancy) → **Supply & construction** (vic_approvals, vic_activity, vic_land, vic_input_costs, au_accord tracker) → **Money & credit** (au_cash_rate, au_mortgage_rates, au_lending, au_credit) → **People** (au_population) → **Social housing** (vic_social_waitlist) → **World** (intl_fred, intl_commodities) → **News** (full filterable archive: tag + source filters, hero-excluded story list).
5. **Detail modal/view** — every chart and tile opens one (see §5).

Geography behaviour: a series without the selected geography renders at its nearest available scope with a small scope chip ("Australia-wide") — shown, never hidden. The World section is exempt. Auctions (`vic_auctions`) render in Prices when data exists; failed sources get honest cards (§7).

## 4. Filter bar and URL state

All shareable state lives in the **query string** of the single `index.html` — never URL path segments (GitHub Pages has no rewrite layer; path links 404). Canonical params: `?range=5y&geo=melbourne&s=vic_hvi&vs=au_hvi` (range, geography, open detail series, compare series).

History rules (explicit):

- Filter changes → `history.replaceState` (no history spam; Back never walks through filter states).
- Opening a detail view → `pushState` (Back closes it).
- Opening via a shared link → `replaceState` (Back exits the site cleanly); focus goes to the modal heading.
- A `popstate` handler restores full state from the URL — the URL is the single source of truth; no router library.

Filtering is instant and client-side: charts crossfade ~200ms, numbers re-count. Precomputed picks (hero, story ranks, findings) apply to the **default unfiltered view only**; filtered views recompute deltas client-side from the raw series (which is why tiles ship machine values, §6).

## 5. Charts, modals, micro-interactions

**Charts** are bespoke React SVG components; math from `d3-scale`, `d3-shape`, `d3-array` only — no chart framework. Cards carry minimal-decoration charts; the detail view carries full axes. Desktop hover: crosshair + our own tooltip (date, value, delta vs previous observation), snapping to nearest point. Keyboard: at most **one tab stop per chart**; the accessible equivalent is the finding sentence (programmatic summary via `aria-describedby`) plus a **disclosure-toggled data table** under every chart. No per-point arrow navigation.

**Touch:** every chart's interactive surface sets `touch-action: pan-y` — vertical swipes always scroll the page. On phones the main-page charts don't scrub at all: **tap opens the detail view**, where scrubbing works in isolation. Tooltips hide on `pointercancel`, dismiss on tap-elsewhere or scroll, and never cover the point being read.

**Detail modal / view.** Desktop: centered modal, backdrop, focus trap, scroll lock, Esc closes. Mobile: a **full URL-driven view** (not an overlay — eliminates iOS scroll-lock problems), `100dvh` (never `100vh`), safe-area bottom padding. Contents: finding headline; full-history chart with local range control (inherits global, adjustable); stat block (latest, MoM, YoY, period range); provenance block (source name + link, data vintage "Data to {date}", next expected release); actions: **Download CSV** (client-side blob from loaded data) · **Copy link** (canonical URL; button flips to "Copied ✓") · **View source** · **Compare** (picker grouped by section → overlay on labelled right axis, `&vs=` in URL).

Close behaviour (explicit table — Safari has no close-watcher API, so this is hand-rolled):

| Opened by | Closed by X / Esc | Closed by Back / edge-swipe |
|---|---|---|
| Card click (pushState) | `history.back()` — consumes the entry | Closes; focus returns to the invoking card |
| Shared link (replaceState) | `replaceState` stripping `s`/`vs` (no entry to pop); focus to page top | Back exits the site (correct) |

**Micro-interactions:** card hover — border sharpens + slight lift + expand affordance (150ms); numbers count up once on viewport entry; scrollspy underlines the active chip; staleness chips keep the fresh/due/stale/failed vocabulary. First paint renders a skeleton of the final layout (no spinners); charts draw in as data lands.

## 6. Data layer and export contract

**New `pipeline/export.py`** reads `data/series/`, `data/meta/` and `data/news/` and writes two files into `web/public/data/` (gitignored — generated in the workflow before every build, and locally via `.venv\Scripts\python.exe -m pipeline.export`; the committed CSVs remain the only stored data):

- **`site.json`** — all series + metadata + annotations + hero picks + finding headlines.
- **`news.json`** — news items (with `tags`) + story ranks + digest text. Fetched **eagerly in parallel** with site.json (Today needs it on first paint; it's ~27KB compressed — laziness saves nothing).

Measured payload for the whole dataset: ~88–134KB compressed. **No downsampling, no per-section splitting** — explicitly rejected as over-engineering.

Contract rules (each is load-bearing):

- Top level: `schema_version` (integer, bump on breaking change) and `generated_at` (ISO UTC).
- Each series entry: `{ status: "ok" | "failed", meta: {...}, points?: [...] }` — **absent data is a first-class state**. `vic_auctions` and `vic_median_price` are `failed` in today's real data; the front-end type system handles this from day one.
- Series meta carries: source name + URL, unit, frequency, last data date, `last_fetched`, `last_changed`, cadence thresholds (days-until-due / days-until-stale), next-release note.
- **Machine values, not display strings**: numeric value, numeric delta, ISO dates. One small TypeScript formatter map (~20 entries mirroring the Python registry) renders them. No pre-formatted "$820k" strings in the JSON.
- **Time stays client-side**: Python computes editorial selection (hero picks, story ranks, findings — via `pipeline/scoring.py` and `pipeline/findings.py`); the browser computes everything time-relative (staleness badges, "updated N days ago") against the visitor's clock, always shows the absolute vintage ("Data to 31 May 2026"), and shows a site-wide "data may be stale" banner when `generated_at` is older than ~48h. A dead cron can never leave green badges up forever.
- `json.dump(..., allow_nan=False)` — NaN never reaches the wire.

`app/scoring.py` relocates **unchanged** to `pipeline/scoring.py` (test anchors 13.00/6.01/1.24 move with it). New `pipeline/findings.py` holds per-series headline rules (direction, magnitude, vs-target phrasing), pytest-covered per series. The raw CSVs in `data/series/` remain the provenance layer; the browser never parses CSV.

Contract enforcement (no JSON-Schema codegen — rejected as overkill): (a) pytest runs export over pinned fixtures and validates shape; (b) a validation gate **inside the daily workflow** blocks a malformed export from being committed; (c) the site does a small runtime shape check that fails loudly; (d) checked-in fixtures: one or two real exporter outputs plus hand-written edge states (failed scrapers, empty series).

## 7. Honest failure states

- Failed sources: an honest card — "Source blocked since {date}" — with last-known-good data if any exists; never a blank, never a pretend-chart.
- Stale series: chip vocabulary (due/stale) computed client-side from cadence thresholds.
- `site.json` fetch failure: plain retry state with a link to the GitHub data directory.
- `<noscript>`: one paragraph pointing at the repo.
- Site-wide stale banner per §6 when the pipeline has silently died.

## 8. Front-end architecture

- **`web/`** directory: scaffolded with `npm create vite@latest` (React + TS template; currently Vite 8 — don't pin a Vite version in docs). **React 19** with `^19` ranges. Node **22/lts** in Actions. `package-lock.json` committed.
- **Tailwind v4** (CSS-first config) consuming the token custom properties.
- **`motion`** library (imports from `motion/react` — not the legacy `framer-motion` name) for modal/layout transitions only; plain CSS for hovers and simple transitions; chart draw-ins are SVG/CSS. `MotionConfig reducedMotion="user"` at the app root. LazyMotion only if the bundle budget actually tightens (target: < 200KB gzip total JS).
- Vite `base` set for the repo subpath (`/victoria-housing-dashboard/` or relative `./`); **all data fetches base-relative**.
- No router; the URL-state hook of §4. State: React context for parsed data + the URL hook; no state library.

## 9. CI and deploy

**One workflow, `update.yml`, owns Pages deploys** — never a separate push-triggered deploy workflow. GitHub's documented rule: commits pushed with the default `GITHUB_TOKEN` never trigger other workflows, so a separate deploy workflow would deploy on human pushes but silently never on the daily data update. Layout:

- `update.yml` gains `on: push` (branches: main) alongside the cron/dispatch. The data-pipeline job is skipped on code pushes; the build+deploy job always runs.
- Build happens **in the same job/workspace that just ran the pipeline and committed the data** — never a fresh downstream checkout (which would pin the pre-commit SHA and ship yesterday's data daily). Steps: pipeline (cron/dispatch only) → commit data (`git pull --rebase origin main` before push — the cron fires during Melbourne daytime, races with code pushes are real; cron only) → export (every trigger; reads the CSVs in the workspace) → validation gate (every trigger; a malformed export fails the job and is never deployed) → `npm ci` → `vite build` → `actions/upload-pages-artifact` → `actions/deploy-pages`.
- Concurrency: deploy path uses GitHub's standard Pages group (`group: pages, cancel-in-progress: false`), distinct from the data job's `update-data` group — overlapping deploys can't let an older build overwrite a newer one.
- Permissions scoped per job: `contents: write` on the data job only; `pages: write` + `id-token: write` on the deploy job only.
- No PAT workarounds. Zero effort on Actions minutes (free and unmetered on public repos).
- **`ci.yml`** (new): pytest + Vitest + Playwright smoke on pull requests and code pushes. Note: bot data commits can't trigger it — which is why the export validation gate lives inside `update.yml`; that gate is the only guard that ever sees real-world daily data shapes.
- Rollout checklist includes the one-time manual switch of Pages source to "GitHub Actions".

## 10. Testing

- **pytest** (extends the 77-test suite): export shape validation over fixtures, scoring anchors preserved post-move, findings rules per series, edge states.
- **Vitest + Testing Library**: URL-state round-trips, formatter map, filter logic, finding rendering, design-token pins (ported from `tests/test_theme.py`).
- **Playwright** — small and hermetic: serve the production build locally with checked-in fixture JSON (never live data), Chromium only, two profiles (desktop + Pixel 7), reduced-motion emulation, ~5–10 assertions: loads, filters update charts + URL, detail opens/closes/deep-links, chart-DOM invariants (N series rendered, axis labels present, headline text non-empty). **axe scan folded into this run**, plus exactly four keyboard assertions: tab through the filter bar; modal focus-trap + Esc; chart focusability; animations suppressed under reduced motion.
- **Explicitly no pixel-snapshot testing** (Windows-dev baselines can't serve Linux CI); token tests + DOM invariants carry the design-regression load. The rest of the AA commitment is a manual pre-release pass (keyboard walk, contrast spot-checks, real-phone checks).
- Real-device verification at first deployed preview, on the owner's phone: scroll-past-charts, tap-to-detail, Safari edge-swipe Back, safe-area padding.

## 11. Rollout

1. Build on a feature branch; Streamlit stays live throughout.
2. Acceptance: content-parity checklist vs the live Streamlit app (every series, staleness/next-release affordances, news + stories + digest, hero) + full test suite green + manual AA pass + real-phone checks.
3. First Pages deploy; brief parallel run; team gets the new link.
4. Retire: delete the Streamlit Cloud app, remove `app/` (git history preserves it), rewrite README (stack description, architecture diagram, dev workflow: `npm run dev` in `web/`, `.venv` pytest unchanged), amend `BUILD_BRIEF.md`'s locked-stack note.

## 12. Considered and rejected

Panel-verified rejections, recorded so they aren't re-proposed: React 18 (security-patch-only), pinning a Vite major, LazyMotion-by-default, JSON-Schema + codegen contract, auto-generated cross-language fixtures, pixel-snapshot testing, per-point chart keyboard navigation, payload downsampling/splitting, PAT-triggered deploys, cross-browser Playwright matrix, Actions-minutes engineering, path-based URLs, fully-lazy news, pre-formatted display strings in JSON, baked-in staleness badges, a separate push-deploy workflow, main-page touch scrubbing on phones, custom domain (declined for now — links can't redirect later if one is added).
