# Dashboard 2.5 — Feedback batch: dark identity, headline conveyor, bare headings, personalisation

**Date:** 2026-07-22 · **Status:** approved in brainstorm, pending user spec review
**Feedback source:** user's review-board feedback (4 items), personalisation grounded in a
10-agent research sweep (news/finance/BI/gov-data/UX-literature; 43 patterns).

## 1. Context

Four pieces of feedback on the live 2.4 dashboard
(https://jackalexleonard-stack.github.io/victoria-housing-dashboard/):

1. The headline row (lead-finding card + two secondary cards) should rotate ~every 5 s.
2. Replace the cream identity with the organisation-adjacent purply-blue **#1A1824**
   (sampled from the user's pasted swatches) with off-white text.
3. Collapsed sections show **nothing but the heading** — all closed = a clean list of headings.
4. Personalisation: approved model is the research-backed hybrid (compact customize control +
   shareable URL presets + dismissible hint), **all sections closed by default**, on the
   **unified open/closed state model** (Approach A: tick = expanded; untick = bare heading;
   no separate hidden state).

Non-goals: Streamlit app untouched (cream identity stays there until its user-gated
retirement); no light-theme fallback (`prefers-color-scheme` split explicitly declined);
no drag-reorder and no since-last-visit markers (named follow-up candidates, §6).

## 3. Headline conveyor

Layout unchanged: 1 lead card (sm:col-span-2) + 2 secondary cards (`TodaySection.tsx`).

- **Pool:** ranked findings already exported — `hero_lead` first, then `site.hero` tile order,
  deduped, only keys with a finding + chart (same guards as today). Typically ~6.
- **Advance:** every **5000 ms**, conveyor step: secondary-1 → lead, secondary-2 → secondary-1,
  next pool item → secondary-2, lead exits. The pool cycles (wraps around), so every finding
  passes through the lead slot indefinitely.
- **Pool < 3:** no rotation, no controls — static row exactly as 2.4 (also the graceful state
  for older exports).
- **Pause/resume:** hover over the row, focus-within, detail modal open, document hidden
  (`visibilitychange`), or user-toggled pause. Manual jump (dot click) resets the timer.
- **Controls:** small pause/play button (aria-pressed, aria-label) + one dot per pool item
  ("Show finding N of M"); active dot marks position. 44 px targets on coarse pointers.
- **Reduced motion:** `prefers-reduced-motion` **disables auto-advance entirely** — static row,
  dots/pause still functional. Slide/fade transitions via the `motion` lib under the existing
  `MotionConfig reducedMotion="user"` (belt and braces: the timer itself is off, not just the
  animation).
- **Filters active:** row hidden (2.4 behaviour, unchanged — findings are default-view-only).
- **A11y:** rotating region is `aria-live="off"` (no SR spam); cards stay buttons opening
  their detail modals.
- State is component-local (no persistence of pause/position).

## 4. Sections: bare collapsed rows + unified personalisation

**Bare collapsed rows.** `CollapsedRow` (summary + staleness chip) is **deleted**; a closed
section renders heading + chevron only. Outage honesty lives inside expanded sections
(per-card chips + section outage notice, unchanged) — the user explicitly chose "truly bare"
over a status dot. `collapsedSummaryText`/`honestOverrideText` + tests are removed
(`worstStaleness`/`sectionOutageNotice` stay — still used when expanded). The pipeline keeps
exporting `section_summaries`/`section_summary_quiet` (schema untouched; candidate cleanup
later).

**Default closed everywhere.** `defaultSectionOpen` loses its viewport branch → default is
closed for every themed section (`prices, rents, supply, money, people, social, world, news`)
on all devices. Today is not a themed section and is always visible. Existing `vh.sections`
overrides (`'open'`/`'closed'` records) carry over untouched — only the default flips.

**One state, three surfaces** (approved Approach A — tick = expanded):
1. Heading click toggles in place (as today; jump-links/scrollspy keep auto-expanding).
2. **"Sections" control in the sticky FilterBar** (tune icon + label): popover listing the 8
   themed sections as checkboxes (Today pinned, not listed), plus **Open all** and **Reset**
   (Reset clears overrides + URL param → all closed). Focus-trapped, Esc closes, axe-clean,
   44 px coarse-pointer targets.
3. **`?sections=` URL param** — comma-separated open section ids (e.g. `?sections=rents,money`).
   Precedence at load: **URL > localStorage > default-closed**; unknown ids ignored; empty
   param = all closed. Live state mirrors into the param via `replaceState` (same idiom as
   range/geo). A URL-seeded state becomes the user's persisted state only once they toggle
   something (then written to `vh.sections` as normal). Preset links per teammate's beat are
   the questionnaire-replacement (research: OECD/ABS .Stat, OWID, FRED all converged on URL
   state; first-run wizards rejected — ~70 % skip, no recommender to feed, five-sections
   catalogue).
4. **First-visit hint:** one dismissible line under the conveyor — "Pick the sections you
   follow →" pointing at the Sections control; dismissal in `vh.sectionsHintDismissed`.
   Never blocks anything.

## 5. Testing & rollout

- **Vitest:** conveyor reducer (advance order, pool <3, timer reset on jump) with fake timers;
  sections precedence (URL > storage > default); param serialisation round-trip; token
  contrast tests re-pointed at the dark values.
- **Playwright:** update lead-finding guard (rotation-aware: assert lead present AND advances
  after 5 s with motion allowed); reduced-motion project asserts **no** auto-advance
  (per-test `emulateMedia` + matchMedia precondition — the 2.2 gotcha); bare-heading
  assertion (collapsed row has no text besides heading); default-closed on desktop AND
  Pixel-7 projects; Sections popover keyboard flow; `?sections=` deep link opens exactly
  those sections; axe on the dark theme (the real contrast gate).
- **Pytest:** untouched (no pipeline changes).
- Rollout: normal branch → adversarial review → merge to main → update.yml build+deploy.
  No data-schema change, no migration beyond the default flip (existing overrides honoured).
